# Typed values as jsonb with per-type shape CHECKs; Drizzle migrations are generated only

Values and corrections are stored as canonical jsonb (money `{amount, currency}`, decimals in canonical form with no trailing zeros). A large `VALUE_SHAPE` CHECK, generated by drizzle-kit, rejects floats, non-canonical decimals and bad dates. That makes jsonb equality exact for carry-over. Migrations are never hand-edited: no triggers, no SQL functions, statuses as `text` + CHECK. An empirical spike confirmed drizzle-kit generates every composite and circular FK, partial index and CHECK.

**Considered options:** typed `v_*` columns (duplicated across values and reviews); Prisma (CHECKs need hand-edited migrations); pgEnum (removing a value needs hand-written SQL).
