# Core Tier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task is sized for one subagent dispatch. If an implementer needs exact code steps, expand the task with superpowers:writing-plans first. This plan fixes the files, interfaces, tests and acceptance criteria; the spec fixes the behaviour.

**Goal:** Ship every requirement in `BRIEF.md`, plus the reliability invariants evaluators will exercise: upload → LLM extraction with verbatim evidence → human review → revised version with exact carry-over, surviving restarts and `FLUSHALL`, all from `docker compose up`.

**Architecture:**
- A pnpm 12 / Turborepo ESM monorepo.
- NestJS API and NestJS worker (BullMQ), over Postgres 18 (system of record), Redis 8 (disposable) and S3 (SeaweedFS).
- Pure extraction logic lives in `packages/core`.
- PDFs are parsed in a child-process pool.
- LLM calls go through a provider interface: **Gemini by default**, with an Anthropic adapter. Each call is checkpointed before it is validated.
- A Vite React SPA behind nginx.

**Tech Stack:**
- Runtime and build: Node 24, pnpm 12, Turbo 2, TypeScript, SWC.
- Backend: NestJS 11, BullMQ, Drizzle ORM + drizzle-kit, zod v4.
- PDF: unpdf / pdfjs-dist, tinypool.
- LLM: `@google/genai`, `@anthropic-ai/sdk` 1.14.
- Storage: `@aws-sdk/client-s3`.
- Frontend: React 19, React Router 7, TanStack Query 5, Tailwind 4.
- Tests: Vitest, fast-check, Playwright, axe.

**Spec:** `docs/superpowers/specs/2026-11-27-document-review-design.md` (v5). **§15.3 overrides any conflicting section**, because it records the scope moved to Extended. §15.4 covers the Gemini adapter.

## Global Constraints

- **Hard cutoff:** Core work stops **Sat 28 Nov 2026 16:00 UTC**. After that only verification, deploy, gist, video and submission. Unfinished Core items go into README "Deliberate cuts".
- **Read-only:** never write to `fixtures/` or `jd.md`. `BRIEF.md` is verbatim.
- **Toolchain:**
  - Node 24 (`.nvmrc`), `packageManager: pnpm@12.x`, `allowBuilds` in `pnpm-workspace.yaml`.
  - `postgres:18`, with its volume mounted at `/var/lib/postgresql`.
- **ESM everywhere:**
  - Packages: `nodenext` with `.js` relative imports.
  - Nest apps: SWC builder with `moduleResolution: bundler`, entry point `dist/src/main.js`.
- **Migrations:**
  - Generated only. No triggers or functions. Statuses are text + CHECK.
  - No Drizzle `.desc()` indexes. Regexes as `String.raw` + `sql.raw()`.
  - PKs are `uuid DEFAULT uuidv7()`. `updated_at` is set in SQL.
- **Lock order:** `documents → document_versions → extraction_runs → llm_calls → extracted_values → reviews`. Writes run at READ COMMITTED; multi-query reads use REPEATABLE READ READ ONLY. The idempotency-key table is Extended, so it isn't in Core's order.
- **Leases and caps:** lease 30s, heartbeat 10s, sweep 10s. `MAX_ATTEMPTS` 5. Call cap `max(6, plannedChunks+3)`. Postgres `now()` is the only clock.
- **Limits:**
  - PDF ≤ 10 MB, ≤ 200 pages, text ≤ 2M chars.
  - Parse timeout 30s, child heap 512 MB, RSS kill at 768 MB.
  - LLM timeout 120s, chunk ≤ 400k chars.
- **LLM:**
  - Sentinel tool schema: no nullable unions, no length or item bounds (zod enforces those).
  - Raw response bodies are stored before validation, and SDK retries are off.
  - `LLM_PROVIDER` is `gemini` by default. The provider key goes to the **worker only**.
  - The fake and cassette providers are refused unless `APP_ENV=test`. Dev-default secrets are refused under `APP_ENV=production`.
- **Pagination (Core):** forward-only. Response is `{data, page:{limit, hasMore, nextCursor}}` plus `Link: rel="next"`. Limit 1–100, default 20. Cursor UUIDs are validated. No totals, except the capped `/documents/facets`.
- **Errors:** RFC 9457 problem+json with `code` and `requestId`.
- **Idempotency (Core):** natural guards only:
  - content dedupe on new versions (non-failed, current template)
  - an identical review is a 200 no-op
  - a stale `expectedCurrentReviewId` → 409
  - retry is allowed only from `failed`
- **Tests:** each requirement test carries its ID (`[R#]`/`[I#]`) from `docs/reference/traceability.md`. IDs marked Extended there don't gate Core.

## Review Focus

1. **Invoice v2 carry-over.** After v1 is approved, `invoice-001.v2.pdf` must leave exactly {due_date, total_amount} pending under every quote-span variant, and `vendor_name` must carry over. Tested in Task 5 (unit) and Task 12 (e2e).
2. **Fixture-real parsing.** `4.2%,` `3.8%.` `5%\n` must parse as percent. Dates, quantities and `SD-400` must never parse as money. `$… CAD` is rejected. `(1,234.00) USD` is negative. Tested in Task 5.
3. **Retry paths.** Retry after a failure, and a BullMQ retry inside the lease window after a transient release, must both re-extract without 23505 errors or silent acks. Tested in Tasks 3b and 7.
4. **Concurrent reviews.** Approve, correct and the identical no-op on one document must keep `pending_count` equal to the recomputed value. Tested in Task 8.
5. **Cold start and recovery.** `docker compose up` with no `.env` must reach terminal states, then survive `FLUSHALL` plus `restart`. Tested in Task 13.
